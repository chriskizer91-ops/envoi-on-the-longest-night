## How to work here: what this session learned

- **One browser at a time.** The machine has 4 cores; every command that opens a browser goes through `flock /tmp/claude-0/browser.lock <command>`. Agents' long browser runs can starve the queue for an hour: keep each run short, and cancel queued runs before a delivery. `pkill -f '<pattern>'` also matches your own shell's command line, so it can kill the shell you run it from: find the process ids with `pgrep -f` first.
- **Parallel helpers.** The Workflow tool runs only 2 agents at a time here (4 cores - 2), so for a wide audit the Agent tool's background agents are faster. Give each fixer its own worktree and branch (`hub/fix-<owner>`), the files it owns, and the tests that prove its fixes; merge and run the full pass yourself.
- **Prove a fix with a test that fails on the old code.** The landing bug survived because the world step only ever landed the one way that worked.
- **Before publishing:** build with `--min` (never publish the `--offline` copy); publish `dist/game.artifact.html` with the 22 files in `dist/game.beside.json` at the same paths; the same for the try page (`dist/try.beside.json`); the map editor without `capabilities` (it keeps its database). Read an artifact with the Artifact tool before republishing it from a new conversation.
- **Chris's file:** `node tools/build.mjs --min --offline putting-it-all-together/game.html`, then `node tools/game-test.mjs --offline` (must pass), then send `dist/game.html`; build with `--min` again afterwards. This evening's file also has the four ideas switched on (above).
- **Test timing:** the dialogue box types its lines out, so a check that reads `.talk-said` must wait for the whole line.
